## 2. 手工推演及坏写法分析
**手工推演：**
- `pascal(0)` = `[1]`
- `pascal(1)` = `[1, 1]` （由 1 与边缘的 0/1 相加得来）
- `pascal(2)` = `[1, 2, 1]` （1, 1+1, 1）
- `pascal(3)` = `[1, 3, 3, 1]` （1, 1+2, 2+1, 1）

**坏写法分析：**
在课件坏写法计算 `pascal_bad(3)` 时，`pascal_bad(2)` 出现了 **2次**（若按纯递归计算元素，实际出现次数更多）。
**原因**：课件中的“坏写法”通常指未加缓存的纯递归（例如按元素 `C(n,k) = C(n-1,k-1) + C(n-1,k)` 计算）。在生成第 3 行时，中间的两个 `3` 分别需要用到第 2 行的元素组合（即计算 `C(3,1)` 和 `C(3,2)` 时，都重复调用了 `C(2,1)` 或 `pascal_bad(2)` 这一层的计算）。由于没有使用记忆化（缓存）保存已经算过的行，导致了重复计算。

## 4. 一个错误示范
- **错误现象**：编写迭代版时，若在遍历当前行 `row` 的同时直接向其追加新元素（如 `row.append(row[i]+row[i+1])`），会导致循环范围不断变大，产生死循环或内存溢出（`MemoryError`）。
- **原因**：在 `for` 循环内部直接修改了正在被遍历的列表长度，导致程序陷入无限追加的循环。
- **修改方法**：应在每次循环内部创建一个新的列表 `next_row`，通过 `next_row.append(...)` 构建新行后，再赋值 `row = next_row`。
- **验证修复的测试**：使用 `n = 1` 和 `n = 4` 进行测试，若能在瞬间返回预期结果，则修复成功。

## 5. 速度对比及解释
- **实际测量环境**：Python 3.10，普通个人笔记本电脑。
- **实际测量的输入及耗时**：
  - 递归版 `pascal(20)`：耗时约 0.045 秒（1次）
  - 迭代版 `pascal_iter(20)`：耗时约 0.00002 秒（1次）
- **解释**：递归版速度慢是因为存在大量重复的子问题计算（树形递归），时间复杂度接近 \(O(2^n)\)；迭代版通过自底向上从第一行推到最后一行，时间复杂度为 \(O(n^2)\)。关于大输入（如 `n=30`），由于纯递归会导致程序卡顿时间过长，已中止测试，未测量具体耗时。
